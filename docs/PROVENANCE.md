# The provenance model

Every mask in this corpus can answer three questions: what made me, from what,
and what did a human change afterwards. That is not a labelling convention — it
is the mechanism that lets a generator learn from human corrections without
learning from itself.

> **Where this came from.** Authored for foilkit out of
> `packages/forge/src/provenance.ts` and the corresponding sections of
> [`MASK-PIPELINE.md`](MASK-PIPELINE.md). The code is the specification; this
> document is the reading of it, and where the two disagree the code is right.

---

## The problem it solves

The original ask, from the person who painted the first masks:

> "We'll want to mark when masks are generated by an AI as well, because once
> I've made a few hand-done masks, I want an AI to be able to learn from mine to
> be able to do its best at replicating it across other cards in similar
> sets/series — and then I want to be able to correct the agents' mask such that
> it can then observe the diff and continue to improve without me having to
> hand-paint all the masks."

A loop like that has exactly one failure mode that matters, and it is not
inaccuracy. It is **feedback collapse**: a generator that learns from its own
unreviewed output converges on its own mistakes, confidently, and the corpus
degrades in a way nobody notices until the answers are all subtly wrong
together. Everything below exists to make that impossible rather than
discouraged.

## Three records, one chain

| | Field | What it answers |
|---|---|---|
| 1 | `derivation_method`, `prior.source`, `prior.generator` | What made me |
| 2 | `prior.generator.exemplars`, `correction.parent` | From what |
| 3 | `correction.{parentPng, parentDiffPng, metrics, grid}` | What the human changed — kept as pixels **and** numbers |

The third is the training signal. It is stored as an image because a diff a
generator can look at is worth more than a scalar, and as metrics because a
scalar is what a queue can rank.

## The label is derived, never claimed

`deriveMethod()` decides `derivation_method` by **diffing the saved pixels
against the pixels the claimed starting point actually produces**. A client
cannot assert that it hand-painted something; the pixels either differ from the
prior or they do not.

A caller can only claim a *machine* label by supplying a full
`GeneratorIdentity` — name, version, model id, run id, and the exemplars the run
consumed — which an ordinary HTTP caller has no way to fabricate meaningfully.
`authorship` and `reviewStatus` are recomputed on every read from
`derivation_method`, so a stale or hand-edited file cannot lie about them
either.

This is contract F3 in [`AGENTS.md`](../AGENTS.md), and it is the model the
other three verification states should copy: verification state should always be
something the system **measured**, not something a caller **said**.

## The five methods

| Method | Authorship | Review status | Exemplar weight |
|---|---|---|---|
| `layout-flatten` | machine | human-adjusted | **0** |
| `hand` | human | human-authored | **1** |
| `hand-refined` | human | human-authored | **1** |
| `ai` | machine | unreviewed | **0** |
| `ai-corrected` | mixed | human-authored | **0.6** |

- **`layout-flatten`** — an era or window rect rasterized to pixels. Machine
  geometry, no stroke painted on it. Weight 0 because it teaches the generator
  only the rect the generator already knows.
- **`hand`** — painted from scratch, or straight onto a layout prior. Ground
  truth.
- **`hand-refined`** — painted on top of an existing **non-AI** mask: a bake, or
  an earlier hand mask. Still unanchored by machine output, so still weight 1.
- **`ai`** — machine output no human has looked at. **Weight 0 at any corpus
  size**, forever. This is the anti-collapse rule and it is enforced in code,
  not by convention.
- **`ai-corrected`** — a human edited an AI mask. Real signal, but anchored by
  what the AI proposed: the human was correcting a starting point rather than
  choosing one, so it is deliberately worth less than an unanchored human mask.

`selectExemplars()` is the only sanctioned way to pick training masks. Globbing
the directory is how unreviewed `ai` masks get into an evidence count; the
codify ritual and every generator go through the selector, and the selector
reports **why each rejection was rejected**.

## The ratchet

Regeneration may rewrite any guess and may **never** overwrite a human decision.

A machine write landing on an existing mask **throws** unless it carries an
explicit `supersede: { runId }`. When it does, the replaced mask is archived
byte for byte with sha256 verification **before** anything live is deleted, and
`restore` puts the human pixels back byte-identically. A corrupt archive aborts
before the live file is touched. `supersede.test.ts` is the executable form of
all three sentences.

Human input is monotonic. Guesses are disposable by design — and because every
printing always has an answer, human attention never fills a hole. It **upgrades
a guess to a decision**, and that decision becomes evidence the next generative
pass uses on everything else. Verify six WOTC window cards and the generator
refits against six exemplars instead of two; every unverified WOTC window card
gets a better guess out of it. The corpus improves by circulation, not by
accumulation.

## `frame` — the same rule, applied to space

Sidecar v4 adds one field, and it obeys the derived-never-claimed rule exactly
as the label does.

Masks live in **canonical space**: the physical card, 63 × 88 mm at 8 px/mm =
504 × 704. Before that they were authored at 490 × 674, which is twice TCGdex's
245:337 raster and 1.55% short of a real card. A mask is a stencil, and a
stencil only fits if the picture underneath is the shape it was cut for — so the
stencil is cut to the **card**, and every image source declares its own
transform into that space in [`data/frames.json`](../data/frames.json).

`normalizeSidecar` re-infers `frame` on **every** read, even when the field is
already present, and it infers it from **the mask PNG's own header** wherever the
file is in reach rather than from the `width`/`height` beside it — because a
number in the JSON is a claim and the pixels are not. A hand-edited sidecar
cannot claim a framing its own pixels deny. An image matching no frame record
resolves to `unknown` and is excluded from mask authoring until a record exists:
a silently wrong-frame mask is worse than a blocked one.

v1, v2 and v3 sidecars normalise to the same in-memory shape. That
compatibility is permanent.

## Aliasing — what a mask actually covers

Counting these wrong inflates coverage several times over.

- **Masks alias by `(cardId, scope)`.** Every variant of one card renders the
  same scan — imagery is keyed per card, and a variant carries none of its own —
  so a mask serves every sibling variant whose `prior.scope` matches, newest
  `savedAt` winning. A holo (window) and a reverse (sheet) of the same card must
  never share one.
- **Window geometry aliases scope-agnostically**, per `cardId`: the art box is a
  property of the scan, and a sheet is the same box inverted.
- **Cross-card reuse never aliases.** Two card ids that reprint the same
  illustration cannot be proven identical from a catalog — there is no
  illustration key, illustrator + name is a heuristic, and perceptual hashing is
  similarity rather than identity. Those stay separate rows.

## What a card's verification state actually is

A card is not one unit of work. It is four, each with its own state, each
re-openable at any time:

| Part | The question | Where its state lives |
|---|---|---|
| Pattern assignment | which foil is this | `FoilGuess.match` — card / facet / set / series / heuristic — plus `confidence` |
| Foil footprint | where the foil sits | sidecar `derivation_method` + `reviewStatus` |
| Window geometry | where the art box actually is | presence of a `data/foil-windows` record |
| Composite tuning | how it sits on this scan | `data/foil-canon` + the override layer |

A card can carry a hand-drawn mask and a pure-heuristic pattern assignment at
the same time. That is a partially-verified card, and a contribution queue
should see it that way. There is no completion state and no backlog with a
bottom.

## Where the corpus stands

At the extraction: 21 card directories, 20 live sidecars (all v4, all
`canonical` frame), 86 live mask PNGs at 504 × 704, one window-geometry record,
and zero per-card overrides — that layer has code and no data, and never has had
any. By derivation method the live masks are 2 `hand`, 3 `hand-refined`, 10
`ai-corrected`, 5 `ai`. The pre-migration originals are kept under
`superseded/`, at the raster they were authored in, which is why they are
deliberately exempt from the canonical-raster check.

Five unreviewed `ai` masks in a twenty-mask corpus is not a defect. It is the
loop running: they are proposals, they are weight 0, and correcting one is the
single highest-value thing a contributor can do to it.
